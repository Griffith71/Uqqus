{# AdSense, and the script that fills the ad boxes and puts in-feed ads between post cards (routes/ads.py ads_script). Google's consent banner for the UK, EEA and Switzerland comes with the AdSense tag (set up in AdSense, Privacy & messaging). The tag is loaded from here, by script, so that three things happen first and no request goes to Google before them: - Non-personalised, unless helpers/ads.py personalised_allowed says otherwise, is set before any ad is asked for. - The key made from the member's password goes (CLAUDE.md "Chat encryption"). It lives in this tab's sessionStorage, so a tag running in another tab can't read it, and it is gone before a tag runs in this one. A page kept by the back button brings its running tag back, so the key goes then too, and an older copy in localStorage goes with it. Not only on `pageshow`: Chromium gives a restored page `resume` and `visibilitychange` before it (measured, scripts/ui/ads.spec.ts), and a tag's own listener for those would read a key a sign-in in this tab wrote while the page was away. So the key goes on each of them too (and on `focus`), in listeners put on before the tag is, with capture, which run first. On `pageshow` the hold below is asked again, and a page that would be held now is drawn afresh (`location.reload`), which ends the tag that came back with it. - A browser holding chat data that isn't this page's account's gets no tag at all and its boxes fold (partials/ad_hold.html). All of this is asked when the tag loads. A tag already running in another tab stays until that page is left: it goes on running beside a log out or a chat opened elsewhere.
