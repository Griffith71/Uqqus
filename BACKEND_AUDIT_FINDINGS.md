# Backend audit findings

Audited 2026-09-18: a full read-through of `ruqqus/routes/`, `ruqqus/classes/`, and `ruqqus/helpers/` (~22,500 lines) looking for logical errors and inconsistencies, split across 5 parallel subsystem passes (content core, guilds/boards + moderation, users/auth/identity, admin/payments/discovery, helpers). Templates and JS were not covered by this pass.

This is a findings list for later fix work — nothing here has been changed. Check items off as they're fixed. Each item cites file:line as of this audit date; line numbers may drift as the codebase changes.

---

## Critical — security / permission bypass

- [ ] **`ruqqus/helpers/security.py` `safe_compare()`** (used by `login.py:128`, `settings.py:270` to validate MFA recovery codes) — not actually constant-time: does plain `x==y` then pads total latency with a random sleep, which masks but doesn't eliminate the timing signal, and can call `gevent.sleep()` with a negative duration if the padding budget is already exceeded. The file already has the correct primitive (`hmac.compare_digest` via `validate_hash`, line 18-20) — `safe_compare` should just use that.
- [ ] **`ruqqus/helpers/wrappers.py:319-320` `is_guildmaster` decorator** — checks `v.is_banned and not v.unban_utc`, which only blocks *permanent* bans. A moderator with an active **temporary** ban passes through (since `unban_utc` is truthy), and `is_guildmaster` is the only ban gate on guildmaster routes (they sit under `@auth_required`, never `@is_not_banned`). A suspended mod keeps full moderation powers for the duration of their ban.
- [ ] **`ruqqus/routes/comments.py:82-119` + `264-266`** — for API requests, a mismatched `pid`/`cid` pair skips the canonical-redirect and its board-ban/NSFW gating entirely, since those checks run against `get_post(pid)` (an attacker-supplied, unrelated post) while the response still serializes the *real* comment's data. A crafted `pid` pointing at a public post can pull content from a comment that actually belongs to a banned/NSFW-gated post.
- [ ] **`ruqqus/classes/board_relationships.py:24`** — the `perm_chat` column is commented out, but `Board.has_mod(v, "chat")` (`ruqqus/classes/boards.py:275`) does a raw `__dict__["perm_chat"]` lookup with no default. Any partial-permission guildmaster (not `perm_full`) running a chat mod command (`/ban`, `/kick`, `/gm`) hits an unhandled `KeyError`. Routes gated via the safer `is_guildmaster("chat")` decorator (which uses `.get()`) just silently always deny instead — two different broken behaviors from the same missing column.
- [ ] **`ruqqus/routes/admin_api.py:243,267` vs `:86,124`** — `api_ban_comment`/`api_unban_comment` require only `admin_level_required(1)`, while the equivalent `ban_post`/`unban_post` require level 3. Any level-1 admin can unilaterally ban/unban any comment site-wide with content-moderator-tier access, with no ownership restriction.
- [ ] **`ruqqus/routes/flagging.py`** — `api_flag_post` (line 14) and `api_flag_comment` (line 55) have no `@validate_formkey`, unlike essentially every other content-mutating POST route in the app (127 other call sites do have it). Reporting content is CSRF-exposed.

## Critical — crashes on realistic input

- [ ] **`ruqqus/routes/admin_api.py:619-652` `admin_csam_nuke`** — references undefined `url` (should be `post.url`) for any CSAM-flagged post hosted on `i.ruqqus.com`. The resulting unhandled exception means none of the bans (post/user/alts) persist, since it crashes before `after_request`'s auto-commit runs. The `ModAction` audit entry is also never `g.db.add()`-ed even on the path that doesn't crash.
- [ ] **`ruqqus/routes/boards.py` `mod_edit_rule`** (~1204-1226) — builds a `Query` object via `g.db.query(Rules).filter_by(id=r)`, never calls `.first()`, then does `g.db.add()` on the Query object itself. Every call raises `UnmappedInstanceError`. No template currently calls it, which is presumably why it's gone unnoticed.
- [ ] **`ruqqus/routes/boards.py` `toggle_guild_bell`** (~2531-2545) — references undefined `board` (the local variable is `guild`). `NameError` on every non-subscriber hitting this endpoint.
- [ ] **`ruqqus/routes/front.py:538` `/subcat/<name>`** — references undefined `sort_method` (the local variable is `sort`). Every request to this route raises `NameError`; the route is completely broken.
- [ ] **`ruqqus/routes/front.py:80-104` `/notifications/posts`** — the API branch references `listing`, which is never defined in this function (leftover from the sibling `notifications()` function). `NameError` on any API-content-negotiated call.
- [ ] **`ruqqus/classes/mod_logs.py` `ModAction.title_text`** (~133-140, via `note` ~51-62) — crashes (`TypeError: argument of type 'NoneType' is not iterable`) whenever an exile action has no target post/comment (the common case — `thing` is optional on the exile route). Breaks the mod-log detail page for most exile entries.
- [ ] **`ruqqus/routes/login.py:496-502,534-539`** `get_reset`/`post_reset` — dereference `user.login_nonce` before the `if not user` check, so a bad/stale reset-link `id` 500s instead of hitting the intended 404.
- [ ] **`ruqqus/routes/admin_api.py:218-240` `api_sticky_post`** — skips the not-found guard every sibling handler has; a bad `post_id` falls through to `post.stickied = True` on `None` → `AttributeError`.
- [ ] **`ruqqus/routes/paypal.py:142`** — `jsonfy` typo (undefined name, should be `jsonify`) on the "promo code no longer valid" branch, reached after a PayPal capture may already have started.
- [ ] **`ruqqus/routes/giphy.py:15`** — `/giphy` crashes (`ValueError`) whenever `limit` isn't supplied, since `int(request.args.get("limit", ""))` → `int("")` raises before the function's own fallback branches for that exact case ever run.
- [ ] **`ruqqus/routes/giphy.py:11-12`** — `/giphy<path>` crashes (`TypeError`) on any match, since the URL rule declares a `path` variable but `giphy()` takes no parameters.
- [ ] **`ruqqus/classes/paypal.py:258-278` `PromoCode.promo_text`** — `UnboundLocalError` for a flat-discount promo missing `flat_cents_min`. `adjust_price()` on the same model (~207-230) has the same unguarded-None assumption (`TypeError` on `int >= None`).
- [ ] **`ruqqus/helpers/aws.py:152-215` `check_csam(post)`** — references undefined `v` (copy-paste from the sibling `check_csam_url(url, v, ...)`), would `NameError` if ever called. Currently dead code (zero callers — every real call site uses `check_csam_url` instead), but broken if anyone wires it up.
- [ ] **`ruqqus/classes/userblock.py:32-34` `__repr__`** — references bare `user`/`target` instead of `self.user`/`self.target`. `NameError` if `repr()` of a `UserBlock` is ever triggered (debugger, logger, unhandled-exception page).

## High — content visibility / inconsistent behavior

- [ ] **`ruqqus/classes/user.py:268-278` `User.idlist`** (home feed) — selects `Follow.user_id` (always just `self.id`) instead of `Follow.target_id`. The "show posts from people I follow" mechanism is a complete no-op.
- [ ] **Same method, ~300-311** — only filters "authors I've blocked"; "authors who blocked me" is explicitly commented out, unlike every sibling listing method (saved/history/upvoted/downvoted), which enforce both directions.
- [ ] **`is_nsfl`/`hide_offensive`/`hide_bot` filters are inconsistent across `ruqqus/classes/user.py`'s listing methods** — `userpagelisting`, `forwarded_idlist`, `saved_idlist`, `saved_comment_idlist`, `history_idlist`, and `_voted_post_idlist` are all missing filters that the home feed and `commentlisting`/`_voted_comment_idlist` enforce. NSFL content can appear on profile/saved/history/upvoted tabs even though it's meant to be unconditionally gated.
- [ ] **`ruqqus/routes/settings.py:54` `filter_nsfw` toggle is inverted** — every sibling toggle assigns `request.values.get(x) == 'true'` directly; this one assigns the negation. The checkbox does the opposite of what it says.
- [ ] **`ruqqus/helpers/wrappers.py:23` `get_logged_in_user`** — the OAuth Bearer-token path only activates for `/api/v1/*`. Every `/api/v2/*` route silently ignores a valid `Authorization` header and falls back to session-cookie-only auth — token-based API access to v2 doesn't work at all.
- [ ] **`ruqqus/helpers/get.py`: `get_post` never sets `_is_subscribed` on the post itself** (only on `post.board`), while `get_posts` sets both. Confirmed live impact: `ruqqus/helpers/jinja2.py`'s crosspost/embed filter uses `get_post()` + `submission_listing.html`, which gates the "join this guild" banner on `is_subscribed` — always shows the prompt to already-subscribed users on embedded/crossposted views.
- [ ] **`ruqqus/helpers/get.py`: `get_comment`/`get_comments` are missing `invite_rescinded=False`** in their moderator-status subquery (present in `get_post`/`get_posts`). A removed guild moderator keeps guildmaster-level comment visibility (seeing blocked users' comments, mod-only UI) indefinitely. Mutation routes are separately guarded, so this is a visibility leak, not a full write bypass.
- [ ] **`ruqqus/classes/boards.py:234` `Board.idlist`** — `posts.filter_by(is_pinned=False)` result is discarded, not reassigned. Pinned-post exclusion from the ranked listing is a complete no-op; pinned posts appear twice on guild pages.
- [ ] **`systemprofile` (the reserved profile-post guild) leaks into public listings** — `ruqqus/routes/front.py:561-563`'s `/browse` exclusion checks a hardcoded `subcat_id != 108`, but the seed script (`scripts/wizard.py`) never sets `subcat_id` (stays at default 0), so it isn't actually excluded — contradicts the `PROFILE_BOARD_NAME`/`get_profile_board_id()` check used consistently elsewhere.
- [ ] **`ruqqus/routes/search.py:230-231` guild search is broken for every logged-in user** — filters on `Submission.user_id`/`is_active`, neither of which exists on `Submission` (copy-paste from what should be a `Subscription` query). Any authenticated `+guild` search 500s; anonymous search works but doesn't exclude `systemprofile` either.
- [ ] **`ruqqus/routes/front.py` `/all/comments`** lets `admin_level >= 3` bypass the banned/deleted filter for comments, while `/all` (posts, via `frontlist()`) has no such bypass at any level. Separately, **`random_comment()`** unconditionally filters NSFW/offensive/bot content regardless of viewer settings, while **`random_post()`** correctly respects the viewer's preferences.
- [ ] **`ruqqus/routes/search.py:75-81`** — computes a properly `%`/`_`-escaped `url` variable for the `url:` search filter, then uses the unescaped `criteria['url']` in the actual `ilike()` call. Wildcard characters in a URL search term get interpreted as SQL wildcards instead of literal text.

## Medium — real but narrower-impact bugs

- [ ] `ruqqus/routes/posts.py:649-669` — the actual `return` rejecting a submission from a banned domain is commented out; posts from most `BAN_REASONS` categories (URL shorteners, copyright, spam, doxxing) still get created despite `domain_obj.can_submit == False`.
- [ ] `ruqqus/routes/posts.py` `repost_post`/`forward_post` have no ban/deleted/purged guard on the target post, unlike their comment-side siblings `repost_comment`/`forward_comment`.
- [ ] `ruqqus/routes/comments.py` `delete_comment` has no idempotency guard (`delete_post_pid` 404s on a second delete; deleting a comment twice silently re-runs the promoted-post cascade).
- [ ] `ruqqus/routes/votes.py` — voting on a post refreshes every derived score column except `score_hot`; voting on a comment refreshes every one except `score_disputed`. Each sibling handler has a different field commented out — looks like an unintentional divergence from a shared original.
- [ ] `ruqqus/routes/login.py:132` — the 2FA "wrong code" retry path builds its resend hash from the `time` *module* instead of the `now` timestamp used everywhere else, so a single mistyped 2FA code forces a full re-login rather than a retry.
- [ ] `ruqqus/classes/user.py:1201-1210` `is_valid` vs `:1268` `is_suspended` disagree on active temporary bans — `admin.py`'s alt-account listing (`is_valid`-gated) lists a currently-suspended alt as if it weren't banned.
- [ ] `ruqqus/routes/boards.py` `board_mod_perms_change` is missing the existence check its sibling `mod_remove_username` has — targeting a non-moderator crashes (`AttributeError` on `False.id`).
- [ ] `ruqqus/routes/boards.py` `mod_remove_username` has no self-target guard (unlike the exile route) and skips the zero-mod cleanup `mod_step_down` performs — a sole guildmaster removing themselves via this route can leave the guild permanently private/restricted with no moderators.
- [ ] Inconsistent admin-level thresholds for "view a banned guild's read-only pages": `board_name`/`multiboard` use `>=3`, `board_mod_log` uses `>=4`, `board_about_mods`/`board_about_css` have no admin bypass at all.
- [ ] `ruqqus/classes/boards.py` `has_ban` (admin immunity `>=2`) vs `has_chat_ban` (`>=4`) — asymmetric with no explanation.
- [ ] `ruqqus/routes/admin_api.py:450,452` `user_stat_data` — uses Python `is not None` identity checks instead of SQLAlchemy filter expressions; both stats silently report the total user count regardless of the intended condition.
- [ ] `ruqqus/routes/admin.py`/`admin_api.py` `admin_domain_domain`/`admin_ban_domain` — escapes `_` for an `ilike`-style query but then uses it in a plain equality `filter_by`, breaking lookups for any domain containing an underscore.
- [ ] `ruqqus/routes/admin.py` flagged-posts/flagged-comments listings join against `Flags` without `.distinct()`; content with multiple flags gets duplicated across the paginated window.
- [ ] `ruqqus/routes/front.py:305` `home()` allows `page=0` (unlike `front_all()`/`subcat()`, which floor to 1), producing a negative SQL `OFFSET` and a 500.
- [ ] `ruqqus/helpers/sanitize.py` — the restrictive bio-specific HTML allowlist (`_clean_bio`) is never actually used; the only real caller (`ruqqus/routes/settings.py:83`) omits `bio=True`, so bios get sanitized with the much broader "with links" allowlist (headers, tables, images) instead of the intended narrow one.
- [ ] `ruqqus/helpers/wrappers.py:346` `admin_level_required` checks the raw `is_banned` column rather than `is_suspended`, so an admin stays locked out of all admin routes even after their temporary ban's `unban_utc` has already passed.
- [ ] `ruqqus/routes/boards.py` `mod_settings_toggle_banner` is missing the `ModAction` audit-log entry every sibling settings-toggle route creates.
- [ ] `ruqqus/routes/boards.py` `mod_add_rule`'s multi-rule branch (`rule2` present) is a silent no-op — returns success but adds nothing. Currently unreachable from the UI (no template sends `rule2`).
- [ ] `ruqqus/helpers/get.py` `get_comment` — block-status (`blocking`/`blocked`) subqueries are built but never joined/selected (dead code, extra redundant query — the real block check happens via a separate follow-up query).
- [ ] `ruqqus/helpers/get.py` `get_comment`'s and `get_post_with_comments`'s exile-action subqueries are missing `.distinct()`/id-scoping that `get_comments` has — broader-than-needed table scans and potential nondeterministic `_is_exiled_for` values on repeat exile/un-exile actions.
- [ ] `ruqqus/helpers/get.py:742` `get_comments` — `mod` subquery uses `g.db` instead of the function's own `nSession` parameter; latent bug if ever called with a different session (no current caller does).
- [ ] `ruqqus/helpers/get.py` — `no_text=True` is silently ignored on the anonymous (`v=None`) branch of both `get_post` and `get_comment` (only respected on the `v` branch). Currently harmless since both call sites always pass a real `v`.

## Low — dead code, cosmetic-but-real inconsistencies

- [ ] **MRO base-class ordering bug**: `Submission(Base, Stndrd, Age_times, ...)` vs `Comment(Base, Age_times, Stndrd, ...)` — opposite ordering means `created_date`/`created_datetime` resolve to *different* implementations (different date formats — `"%d %B %Y"` vs `"%d %b %Y"` — and different memoization) purely from unrelated class-declaration order. Confirmed via direct MRO test.
- [ ] `ruqqus/classes/mix_ins.py`: `Scores.score`/`Scores.score_percent` fully shadowed/unused dead code (both `Submission` and `Comment` define their own `score` column). `Stndrd.permalink_full` has zero callers and would crash (`app['...']` subscript instead of `app.config[...]`) if ever called.
- [ ] `ruqqus/classes/submission.py`: `is_archived` is defined twice (~245-247 and ~274-281); the first is dead. `json()` (~509) has `data["comment_count"]: self.comment_count` — a colon instead of `=`, a no-op statement (currently masked/harmless since `comment_count` is already set correctly elsewhere in the dict).
- [ ] `ruqqus/classes/submission.py:622` and `ruqqus/classes/comment.py:524` — identical dead `return output` after an already-exhaustive `is_guildmaster()` in both classes; would `NameError` if ever reached (copy-paste into both siblings).
- [ ] `ruqqus/classes/comment.py:98,536-538` — the `board` association_proxy is fully shadowed by a later `@property board` of the same name (verified via direct attribute-resolution test) — dead declaration.
- [ ] `ruqqus/classes/comment.py:484` `self_download_json` checks `is_banned` twice (copy-paste) instead of also checking deletion, unlike the correctly-written `Submission.self_download_json` (`submission.py:664`).
- [ ] `ruqqus/classes/boards.py:263-268` `has_mod`'s memoization cache-checks key `"_mod"` but writes key `"mod"` — cache never hits, defeats the intended memoization (no correctness impact, just always re-scans).
- [ ] `ruqqus/classes/lodges.py` `Lodge` — entirely unused model, zero live references anywhere in the repo (only commented-out references in `mod_logs.py`).
- [ ] `ruqqus/classes/mod_logs.py` — `unset_nsfl`'s `title` text (~338-343) says "nsfw" instead of "nsfl" (copy-paste from the `unset_nsfw` entry directly above it).
- [ ] `ruqqus/chat/chat_routes.py:56,73` never passes `v` to `get_guild()`, so `Board.has_subscriber()` always reports "not subscribed" in the chat UI regardless of actual status.
- [ ] `ruqqus/helpers/wrappers.py:454-461` `api()` — the `no_ban`-conditional suspension check is unreachable in effect (an unconditional identical check right after it always fires first regardless); `no_ban=True` is never passed anywhere in the codebase. (Found independently by two separate audit passes.)
- [ ] `ruqqus/routes/discord.py` — two routes both registered for `GET /guilded` (lines ~24-26 and ~170-172) with different redirect targets; the second is permanently unreachable (confirmed via direct Werkzeug routing test — first-registered rule always wins).
- [ ] `ruqqus/routes/feeds.py:47-50` — a guard `if not username and key` can never fire, since `username` is a required non-empty path segment.
- [ ] `ruqqus/classes/ips.py:22` `Agent.banned_by = Column(Boolean, ForeignKey("users.id"))` — wrong column type for a foreign key; currently dead since nothing constructs `Agent` anywhere in the repo.
- [ ] `ruqqus/classes/badges.py:30-36` `BadgeDef.json_core` has no `return` statement (always implicitly returns `None`); `:90-92` `Badge.json` is missing its `@property` decorator, making it a plain method unlike every other model's `.json`. Both currently unused.
- [ ] `ruqqus/routes/search.py` `search_guild()` has no API/JSON response branch unlike its sibling `search()`, which supports full content negotiation via the same underlying `searchlisting()` engine.
- [ ] `ruqqus/routes/search.py` `searchparse()` — on a repeated search key (e.g. `author:bob author:alice`), only the last value's exact substring gets stripped from the free-text query, so the first occurrence's text can leak into the free-text search term. Low real-world likelihood.
