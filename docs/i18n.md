# Interface languages: how to mark text

The interface is shown in the reader's own language (the owner, 2026-10-24): a member's "Your language", a visitor's
footer choice or browser language, English when there is no catalogue. The languages are the site's own
LibreTranslate's (helpers/languages.py `ROWS`), and the catalogues are machine-translated by it
(`scripts/i18n_catalogs.py`). Rules: `ruqqus/helpers/i18n.py`; runtime: `ruqqus/helpers/i18n_runtime.py`; scripts:
`ruqqus/assets/js/i18n.js`. **English output never changes**: marking a string only makes it translatable.

## The rules that matter most

1. **One string is one whole sentence (or label).** Never glue translated pieces together, never translate a fragment
   ("comments in +", "on \""): word order differs between languages. Rewrite the markup so the sentence is whole and the
   moving parts are named values.
2. **Named values only**: `%(name)s`. Never positional `%s`, never `{}` / `.format` / f-strings inside a marked
   string, never `+` concatenation of a marked string with words.
3. **Every marked string is a format string**: a literal percent sign is `%%` (`_("100%% sure")`). Inside
   `{% trans %}` write a plain `%` (Jinja doubles it).
4. **The site's name** inside a sentence is `%(site)s` (filled in automatically). `{{ 'SITE_NAME' | app_config }}`
   stays only where the name stands alone (a logo, `<title>` made only of the name). **`site` and `num` are reserved
   names**: never use `%(site)s` for anything else (another website is `%(service)s`, `%(network)s`...), and `%(num)s`
   only for the number a plural is chosen by.
5. **Plurals** always with `ngettext` / `trn` (`%(num)s` is the number). Remove every `{{ 's' if n != 1 }}` and
   `'s' if ... else ''`: other languages have up to six plural forms.
6. **Short, ambiguous words** get a context: `pgettext("button", "Post")`, `pgettext("noun", "Post")`,
   `pgettext("verb", "Forward")`, `pgettext("button", "Block")`, `pgettext("menu", "Save")`. Optional for longer text.
7. **Translator notes** for anything unclear: a comment right above the call starting `Translators:`
   (`{# Translators: the number of people watching a live thread #}`, `# Translators: ...`, `// Translators: ...`).
8. **English output stays byte-identical** (spacing aside where markup forced it): marking never rewords.
9. **Terminology** (CLAUDE.md): the English keeps the site's words (post, comment, forward, repost, guild...).
   `tests/test_terminology.py` still reads the English source.

## Templates (Jinja)

| What | How |
|---|---|
| Text | `{{ _("Save changes") }}` |
| With values | `{{ _("Welcome back, %(name)s", name=v.username) }}` (values are escaped) |
| A link or markup in a sentence | `{{ _('Read the <a href="%(url)s">rules</a> before posting.', url="/help/rules") }}`: the English HTML is ours and trusted; values are escaped. Markup made by a macro (a user link) is passed as a value: `{{ _("%(who)s forwarded this post", who=user_link(u)) }}` |
| An attribute | `title="{{ _('Hide this post') }}"`, `aria-label="{{ _('Close') }}"`, `placeholder="{{ _('Search') }}"` |
| A choice inside an expression | `{{ _("Pin") if not p.is_pinned else _("Unpin") }}` |
| A plural | `{{ ngettext("%(num)s comment", "%(num)s comments", p.comment_count) }}`; for a formatted number pass it: `ngettext("%(count)s comment", "%(count)s comments", n, count=n|compact_count)` |
| Long text with values | `{% trans name=u.username, n=count %}…{{ name }}…{{ n }}…{% endtrans %}`: only plain names inside, no filters, no `{% if %}`; a choice becomes two whole sentences in `{% if %}`/`{% else %}` |
| In an inline `<script>` | `{{ _("Saved") \| tojson }}` |
| Stored English (a label from Python marked with `N_`, a ban reason the site wrote) | `{{ msg_text(x) }}` (not `msg`: many templates are given a `msg` notice of their own) |
| Help pages (inside `{% filter markdown %}`) | each paragraph, list item and heading's text in its own `{% trans %}…{% endtrans %}`; the markdown prefix (`## `, `* `, `1. `, `> `) stays outside the block; markdown links and `**bold**` stay inside; code blocks, operator examples (`from:@x`) and anything a reader types as it is stay unmarked. A Jinja value in the paragraph is passed in: `{% trans limit=bot_rules.DAILY_CAP %}…{{ limit }}…{% endtrans %}` |

**Never mark**: CSS classes, ids, URLs, `data-*` values a script reads, form `value`s the server reads, `name`
attributes, Font Awesome names, emoji, user content, usernames, guild names, numbers alone, the admin pages
(`templates/admin/*`), the legal pages (Terms, Privacy, Rules and the rules card, DMCA, counter-DMCA, the legal
pages, canaries, csam, `templates/legal/*`), `errors/502.html`, `errors/503.html`.

**Don't** assign to `_` (`{% set _ = ... %}`): use `{% do list.append(x) %}`.

## Python

```python
from ruqqus.helpers.i18n_runtime import tr, trn, trp, tr_lazy, N_, msg

return jsonify({"error": tr("You are blocking @%(name)s.", name=u.username)}), 403
return render_template("submit.html", v=v, error=tr("Choose where to post."))
text = trn("%(num)s person", "%(num)s people", n)
LABELS = {"board": tr_lazy("Message board"), "call": tr_lazy("Call")}      # shown only: translated when used
```

* **Module constants** that are only shown: `tr_lazy("...")` (translated each time it is used, in that request's
  language; a test outside a request sees the English, and `==` with a str still works).
* **Anything stored or compared**: keep English. A ban reason, a mod-log note, a draft's error, a bot's last error, a
  value a test or the client compares: `X = N_("...")` (marked, still a plain str) and show it with `msg(X)` (Python)
  or `msg_text(X)` (templates). Never store a `tr_lazy` (the database can't).
* **Notifications**: `notify(user, N_("You have been overthrown from +%(guild)s."), guild=b.name)` and
  `notify_many(ids, N_("..."), **values)` (helpers/alerts.py) instead of `send_notification(user, f"...")`. Links:
  `[%(title)s](%(link)s)`. The English is stored as before; each reader sees it in their language.
* **Emails**: render inside `with force_locale(locale_for_user(user)):` (subject included).
* **Never translate**: logs, exceptions nobody reads, API enum values (`bot_refusal`, `refusal`, `kind`), Matrix and
  oEmbed strings, strings parsed or matched elsewhere (`quote_cards` reading "on X"), the admin routes
  (`routes/admin*.py`), emails to admins, search operator keywords.
* `tr()`'s text must be a literal (the extractor can't read a variable): never `tr(x)`, `tr(f"...")`, `tr("a" + b)`.
* Never `_` in Python (the code has many throwaway `_` variables).
* **Dates and numbers** shown to the reader: `date_text(ts, "%d %B %Y")`, `datetime_text(ts, "%d %B %Y at %H:%M")`,
  `number_text(n)` (helpers/i18n_runtime.py, also Jinja globals): English stays exactly as `strftime` / `{:,}` wrote
  it; other languages get Babel's. Ages and durations ("5 minutes ago", "3 h") with `trn` so English is unchanged.
* The public API (`/api/v1`, `/api/v2` with a token) is answered in English automatically: mark the shared messages
  anyway.

## Scripts (assets/js, assets/chat_src)

```js
toast(tr("Saved."));
el.textContent = tr("Block @%(name)s", {name: name});
label.textContent = trn("%(num)s member", "%(num)s members", n);
date.toLocaleDateString(I18N.intl, {month: "long", day: "numeric"});
```

* `tr` / `trn` are `window.tr` / `window.trn` (assets/js/i18n.js, loaded first on every page; the chat bundle calls
  them at run time). Never name a variable or parameter `tr` or `trn`.
* The first argument is a literal; values go in the object. No concatenation of translated pieces.
* Dates and numbers: `I18N.intl`, never `[]` / `undefined` (the browser's language may not be the page's).
* Never change a code or a value (`'not-author'`, class names, data attributes, event names).

## Checking your work

* `PYTHONPATH=. .venv/bin/python scripts/i18n_lint.py <your files>`: unmarked text (and templates that don't parse,
  Python that doesn't compile). Zero, or each remaining finding is not interface text (report it for
  `ruqqus/translations/lint_allow.txt`).
* `.venv/bin/ruff check <your python files>` and the tests that read your files (`.venv/bin/python -m pytest -q
  tests/<...>`). A test that pinned the English source text is updated to the marked form, keeping its point.
* `PYTHONPATH=. .venv/bin/python scripts/i18n_catalogs.py extract` collects every marked string.
* The pseudo-locale (`I18N_PSEUDO=1`, cookie `ui_lang=en-XA`, or `ar-XB` for right to left) shows every marked string
  accented and bracketed: plain English left on a page is unmarked.

## The site's own words

Short words with the site's own sense (Rep, Guild, Space, Forward, Tip, Curation, Flair, Exile...) come out of a
machine in the wrong sense, so they are translated from a glossary instead: `scripts/i18n_glossary_terms.py` lists each
word with its context and meaning (`TERMS`), and the short headings that join one to a value (`HEADINGS`: "Join
+%(guild)s"); `ruqqus/translations/glossary.json` holds their translations, written by Claude with a review per
language. A new label that is one of these words: mark it with the context already in `TERMS` (`pgettext("button",
"Join")`) and it is translated from the glossary. A new word of the site's own: add it to `TERMS`, add its translations
to the glossary, and run `PYTHONPATH=. .venv/bin/python scripts/i18n_catalogs.py glossary` then `compile-js`.
Every glossary entry must fit a width budget (`budget()`: the site's weighted width, a CJK character counts 2): labels in tight spots (`TIGHT`) get a short form, "Rep" each language's own abbreviation. `LABELS` holds the short interface labels the layout audit (`scripts/ui/i18n.spec.ts`, `npm run i18n`) found too wide or wrong; a new label in a tight spot (a tab, a navbar item, a count) belongs there with `TIGHT`; `CHROME` holds the short
labels of the navbar, sidebars, menus, tabs and footer: a new one there is added to `CHROME` with its meaning.
Inside a sentence, shorthand is written out before LibreTranslate sees it (`PLAIN` in `scripts/i18n_translate.py`):
avoid new shorthand in sentences, or add it there.
