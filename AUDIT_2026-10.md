# Feature audit, October 2026

Audited 2026-10-16 at commit `b9220c23d` (branch `Laba-v0.1`). Nothing was fixed; this file is the only change to the repo. Earlier audits are in `BACKEND_AUDIT_FINDINGS.md` (passes of 2026-09-18 to 2026-10-11); this one concentrates on **the site's features and what is missing from them**, especially everything built after 2026-10-11, which had never been audited.

## 1. Summary

The core rules the site promises (who can see a post, anonymity, Circles, the sharing rule, quote cards per reader, one vote per family, polls across copies, the word filter, muting, search operators, the deletion log, community notes, bots) **held up under live testing**. The problems are concentrated in three places:

1. **Money.** Concurrent tips create coins (S0). A double-click on Subscribe charges more than once. A deleted account's paid circle keeps charging its subscribers. Premium buys itself from a member's coins when a page is opened.
2. **Chat and calls.** A one-sided follow by a stranger opens your Inbox and joins you to their groups without consent. Anyone in a "1:1" chat can secretly add a third account. The encryption is not end to end against the site (the server holds and hands out the recovery key) and still loses history on a new device. Any member can use the call relay as a free UDP proxy and exhaust it for everyone.
3. **Abuse controls.** Every rate limit can be bypassed with a forged `X-Forwarded-For`. Display names can copy another account's handle with look-alike letters, which phones show without the real handle.

Also confirmed: every post embed is broken (500); feeds show a post and its forward copies as separate items; the phone navbar covers the top of pages; the product still calls itself "Ruqqus" in many places and its web app manifest opens `ruqqus.com`.

Counts: **1 S0, 9 S1, 20 S2, about 25 S3**, plus a ranked list of missing features (section 6).

## 2. Method and baseline

- **Environment.** The running container predated the newest features and the dev database was 12 migrations behind the code (finding D-02). The image was rebuilt from the commit above, the 12 migrations (2026-10-15 to 10-26) were applied in order (all cleanly), coturn was configured with `scripts/gen_dev_env.py` and started. The dev database was snapshotted first and **restored at the end** (97 tables, row counts identical). Audit accounts' Matrix users left all their rooms and logged out (Synapse is not part of the snapshot).
- **Baseline.** `ruff` clean; **4,210 pytest tests pass**; `web/` typecheck, lint and Prettier pass, Vitest cannot start on the local Node 20.9 (`.nvmrc` asks for 22). `npm audit` of the chat client's production dependencies: 0. `pip-audit` of the packages installed in the image: 12 packages with advisories (D-05).
- **Live testing.** 12 seeded personas (author, stranger who follows the author one way, blocked account, mutual follower, custom-circle member, paid subscriber, co-author, guild founder, admins at levels 3 and 4, bot owner, a third party). Each feature was exercised through its real routes; pages were opened with Playwright at 1440px and 390px with console, network and axe-core checks; a two-browser voice call and a two-browser E2EE message were run with fake devices.
- **Crawl.** Every GET route (280 URLs) as 5 viewers; every state-changing route of the newer features and settings (131) with an empty body. Results in section 4.9.
- **Statuses.** **Confirmed**: reproduced on the running site or by a script. **Traced**: the code path was read end to end (file:line given). **Hypothesis**: plausible, not verified. **Owner decision**: a policy choice.
- **Severity.** **S0**: coins created or lost, an identity or private content leaks to anyone, an account is taken over. **S1**: a feature is broken, abusable or misleading for many people. **S2**: a narrower bug or inconsistency. **S3**: cosmetic or rare.

The test suite says little about the newest features' behaviour: of 158 test files, 60 only search the source text, no test runs against Postgres, and the route modules of the newer features are never executed by a test. Most findings below would not have been caught by `scripts/check.sh`.

## 4. Findings by severity

### S0

**$-01. Concurrent tips create coins.** Confirmed. Five parallel `POST /gift_post/7s?coins=400` from an account holding 499 coins all answered 200: five tip rows (2,000 coins), the post and the Creator Studio show 2,000 coins tipped, but the payer lost only 400 and the author gained 800. **400 coins were created.** `routes/paypal.py` (`gift_post_pid`, the two `with_for_update()` re-reads around lines 286-287) locks the rows but SQLAlchemy hands back the instances already in the session without refreshing them (no `populate_existing()`), so each request writes a balance computed from stale values. The same pattern is in `gift_comment_pid` (lines 365-366) and the paid username change (`routes/settings.py:860`). A coin sells for about $1 and payout rows are kept "for a cash-out later", so this is money. *Fix direction:* move coins with one conditional statement (`UPDATE users SET coin_balance = coin_balance - :c WHERE id = :p AND coin_balance >= :c`), as `circle_store._pay` already does; then reconcile balances against the tip and payment tables.

### S1

**M-01. A one-sided follow by the sender opens your Inbox, joins you to groups and lets them ring you.** Confirmed. `chat_permissions.can_message_directly` (`helpers/chat_permissions.py:21-24`) is true when *either* person follows the other, including when only the sender follows. Live: a stranger who followed the author started a chat that landed in the author's **Inbox**, then created a group with the author, and the author was **joined** (`chat_group_members.status = joined`) with no invitation and no "who added you". Group adds (`routes/chat_groups.py:87-96`, `:149-154`) and calls (`routes/calls.py:186`, ringing every open page) follow the same rule. Requests only catch people who did not think to follow first. *Fix:* the recipient must follow the sender (or mutual); group adds always arrive as invitations unless mutual.

**M-02. Anyone in a 1:1 chat can secretly add a third account.** Confirmed. 1:1 rooms are created with no power-level override (`helpers/matrix_client.py:68-93`); the live room's power levels have `invite: 0`. The stranger, using the Matrix token their browser receives from `/api/chat/token`, invited a third account into the stranger-author room and it joined (members: bot, author, stranger, third). The chat UI identifies "the other person" by Matrix id and never shows members, and both clients encrypt to every member, so the third account reads everything from then on unseen. *Fix:* give 1:1 rooms the group power levels (invite 100); make the client refuse or flag a room with unexpected members.

**M-03. Chat is not end-to-end encrypted against the site, and history is still lost on a new device.** Confirmed. `GET /api/chat/recovery_key` returns the account's decrypted recovery key to any request with a session cookie (`routes/chat.py:65-76`; the password prompt on `/reveal` protects nothing), and `/api/chat/token` mints a Matrix token for any user (`:50-62`). So the server (or anyone holding a session) can read and send as anyone. `assets/chat_src/src/crypto.js:6-9` records this as a deliberate trade-off for convenience, but `CLAUDE.md` and the product say chats are end-to-end encrypted and "the server can never write a message for someone". Yet the convenience is not delivered: the author's own new browser could not decrypt the author's earlier message ("This message can't be read on this device."); `crypto.js` enables the key backup (`:96`) but never loads its key or restores from it (cause: Traced). *Owner decision:* either real E2EE (recovery key the server cannot read) or honest copy; in both cases fix restoring history.

**M-04. Messages sent before the recipient ever opened chat are unreadable forever.** Confirmed (observed). Room keys go only to devices that exist when a message is sent; a member who has not opened chat has no device. The first message of every message request to a new member is affected. The first-run setup is also not atomic (`crypto.js:48-68`, `:92-93`): an interrupted first session leaves the account in a state the code only logs (`:83-90`), never repairs.

**M-05. Any member can use the call relay as a free UDP proxy and exhaust it.** Confirmed in part. Synapse gives TURN credentials to any Matrix token (`/_matrix/client/v3/voip/turnServer` answered the stranger), outside every call rule. The relay refuses private addresses but accepts **every public address** as a peer (`coturn/turnserver.conf.template`), although on this design both sides of every call are relay-only and the only legitimate peer is the relay itself. With 12 allocations of 1.5 Mbps per credential and new credentials every hour, one account can spend `TURN_MONTHLY_GB`, after which calls and Spaces are paused for everyone (fail closed). No traffic was sent to an outside host during the audit. *Fix:* deny every peer but the relay's own address; count usage per user.

**L-01. A Space's listener list is readable by anyone who can open its post, without joining.** Confirmed. `GET /api/spaces/<id>/state` returned every speaker and listener (usernames, Matrix ids, device ids) to an account that never joined and to the blocked account whose join had just been refused ("This Space isn't available."). The card promises "how many, never who" and the rule is "shown to everyone **in** it". For a sensitive Space (recovery, grief) this exposes who listens. *Fix:* the roster only for people in the Space, the host and admins; counts for everyone else; same for the `space:<id>` live topic.

**$-02. A double-click on Subscribe charges more than once.** Confirmed. 10 parallel `POST /api/circles/3/subscribe`: 3 answered 200, 3 payments (30 coins) were taken, and one membership was written with `renews_utc` = now + 30 days (the upsert sets it rather than adding). 20 coins lost. `helpers/circle_store.py` reads the membership, pays, then upserts with nothing locking the member between the check and the payment. *Fix:* lock the member row (or an advisory lock, as `vote_copies` does) or make the payment depend on the membership insert. Check `subscribe_guild` for the same pattern.

**$-03. Paid circles keep charging subscribers after the owner deletes their account.** Confirmed. With the owner marked deleted and a subscription due, `scripts/renew_circles.py --once` renewed it: the subscriber paid 10 coins and the deleted account received them. `renew_due` and `_DUE` (`helpers/circle_store.py:429-460`) check blocks and exiles but never whether the owner or the payer is deleted or banned for good; `delete_account` does not end subscriptions either way.

**I-04. Display names can impersonate another account's handle.** Confirmed. The check (`helpers/display_name_store.takes_a_handle`, `display_names.key`) ignores only case, spaces, dots, dashes and underscores, so `аudit_friend` (Cyrillic а), `audit_fríend` and `audit_friend̶` (combining mark) were saved for another account; "Admin" and "Uqqus Moderators" are accepted too. Bylines hide the real `@handle` on phones (`handle_tag`), so there the fake is all anyone sees. *Fix:* compare a confusables skeleton (Unicode TR39) after NFKC with combining marks removed; reserve staff-like names.

**X-01. Every rate limit can be bypassed with a forged `X-Forwarded-For`.** Confirmed locally; production Traced. `ProxyFix(x_for=3)` (`ruqqus/__main__.py:85`) and the limiter keyed on `remote_addr` (`:257-277`): 150 requests in a minute with a rotating three-entry header all succeeded (limit 100), and so did 20 wrong-password logins (limit 6 a minute). `nginx.txt` shows one nginx hop; behind Cloudflare that is two trusted entries, so the third from the right is the client's own value. The same address feeds the login and posting throttles, the guild limit's network check, the tips self-boost check, creator-fund network flags and view counts. *Fix:* set `x_for` to the real number of proxies, or use `CF-Connecting-IP` with the origin accepting only Cloudflare.

### S2

**M-06. Public broadcast channels can be written to around moderation.** Traced. Writers have power 50, equal to `events_default` (`matrix_client` channel power levels, around line 243), so a writer's own Matrix token posts straight to the room: not rated by the word filter, not counted against 50 a day, not recorded in `broadcast_posts` and therefore **not reportable** (`routes/broadcasts.py:239-246` answers 404). Members have `m.reaction` at 0 and a reaction's key is free text, so members can post unrated text to up to 10,000 people.

**M-07. Matrix and the database disagree after a partial failure.** Traced. Creating a group or adding people calls Matrix in a loop and then `g.db.rollback()` if a call fails (`routes/chat_groups.py:144-157`, `:184-189`); the invites and joins already done are not undone. Result: people in the encrypted room but not in the member list (invisible readers), or orphan rooms.

**M-08. The daily cap of 100 people added to groups can be bypassed.** Traced. `added_since` counts current member rows (`helpers/chat_group_store.py:93-95`) and removing someone deletes the row (`:62-63`): add, remove, add again.

**M-09. Blocks do not stop third parties putting two people in one group.** Traced; Owner decision. `add_refusal` checks only the person adding against the person added (`helpers/chat_groups.py:57-73`). Combined with M-01, someone you blocked can be pushed into a group with you by a friend of theirs.

**$-04. Premium is bought from a member's coins when a page is opened.** Confirmed. Reading `User.has_premium` spends a coin and grants 7 days when Premium has lapsed; the sidebar reads it on ordinary pages (`can_make_guild`, `classes/user.py:1509-1510`) and the after-request hook commits it. Every persona that opened a page went from 500 to 499 coins with a first Premium purchase recorded at that moment; one account's only coin went when it opened Settings. The Premium page does say "Coins are auto-redeemed", but nothing does at the moment it happens, and the coins can be tips the member received.

**$-05. "Premium only" opens for anyone with one coin.** Traced. `has_premium_no_renew` (`classes/user.py:2206-2218`) is true for any account with at least 1 coin, so the gates that use it (paid circles, Creator Studio, insights, ad-free pages) do not require Premium. `can_make_guild` accepts Premium, so 1 coin also bypasses the 250-Rep rule for making a guild.

**$-06. The Premium page's coin terms contradict the features.** Confirmed. "Coins have no cash value and cannot be redeemed for anything other than Premium membership time and username changes" while coins pay for tips, paid circles and Circle guilds and fund a creator-fund cash-out.

**E-01. Every post embed is broken.** Confirmed. `GET /embed/post/<id>` answers 500 for every post: `score_mode(v)` (Rep and scores, 2026-10-14) raises `'v' is undefined` in the embed template. The 2026-10-10 crawl predates the change. Add render tests for the embed templates.

**F-01. Feeds show a post and its forward copies as separate items.** Confirmed. Visitor All and Home, a member's Following and For You each listed the same post two or three times (original plus guild copies). Every bot item doubles too (B-02).

**F-02. A copy in a guild that turned private stays in All.** Confirmed; re-confirms an item open since 2026-10-10. `post_public` is not re-stamped when a guild's privacy changes, so +auditpriv's copy kept appearing in visitor All. The private guild's own page also keeps listing those posts to visitors (Owner decision).

**I-01. Login treats the email as a pattern.** Confirmed. `routes/login.py:85-88` matches `User.email.ilike(username)` unescaped: `%author@%` with the right password logged in, and `audit_author@example.com` logged into the account whose email is `audit.author@example.com` (`_` is a wildcard). Passwords can be guessed against accounts by email pattern, and an email containing `_` can match someone else's first and lock its owner out. `/forgot` escapes `_` (`:498`).

**I-02. A login request with no password crashes.** Confirmed. `POST /login` with only a username answers 500: the `"x"` default sends it to the 2FA branch, which calls `int(None)` (`routes/login.py:124-127`).

**I-05. Deleting an account ignores every October feature.** Traced (one part Confirmed as $-03). `delete_account` (`routes/settings.py:486+`) does not end paid-circle subscriptions, leave or hand over chat groups (the owner becomes a "Deleted account" nobody can replace), close channels or Spaces, end co-authorships, remove stories, revoke linked Google, Microsoft or Dailymotion access, remove the Matrix identity or the stored recovery key, or clear profile details, display name, email and login addresses. It does delete *other people's* blocks of the account.

**I-06. There is no way to download your data.** Confirmed. The only exporter's route is commented out (`routes/users.py`, `my_info_post`) and it only emailed posts and comments.

**U-01. On phones the navbar covers the top of pages.** Confirmed (screenshots). The two-row navbar hides the profile banner and part of the avatar, and the Chat heading; the content has no top offset below 992px.

**X-02. Missing and wrong security headers.** Confirmed. No Content-Security-Policy, no `X-Content-Type-Options` (commented out in `after_request`), and `Cache-Control: maxage=600` (not a valid directive; personalised pages should be `private`) on every non-media response.

**X-03. Videos cannot go full screen.** Confirmed. `Permissions-Policy: fullscreen=()` is sent on every page but calls and Spaces (`helpers/device_access.py:15,32`), which blocks fullscreen for embedded players on post pages and feeds.

**D-01. `schema.sql` loses 10 foreign keys.** Confirmed. Ten `ADD CONSTRAINT ... FOREIGN KEY (board_id);` have no `REFERENCES` (bans, contributors, mods, postrels, forwardrels, comment_forwardrels, submissions x2, subscriptions, curation_guilds): loading the file gives 10 errors and a fresh install has none of these keys. Otherwise `schema.sql` matches the migrated database exactly.

**D-02. Nothing records which migrations a database has.** Confirmed. The dev database was 12 migrations behind and nothing said so; the newest features had probably never run there. Migration files are also dated up to 2026-10-26, ahead of the audit date. *Fix:* a `schema_migrations` table written by each migration, checked at start-up.

**D-03. A missing setup step leaves an open relay.** Confirmed (local setup). Without `scripts/gen_dev_env.py`, `docker compose up` creates `coturn/turnserver.conf` and `synapse/turn_shared_secret` as empty directories and coturn starts with no authentication and no peer restrictions; an unauthenticated allocation and a relay permission to Redis' compose address were granted, with port 3478 open on every host interface. Fail fast when the file is missing.

**D-05. Known vulnerabilities in installed packages.** Confirmed (`pip-audit` of the image). In feature paths: `bleach` 6.2.0 (the sanitizer), `Pillow` 11.1.0 (decodes uploaded avatars and banners, 17 advisories), `markdown` 3.7, `werkzeug` 3.1.3, `flask` 3.1.0, `cryptography` 43.0.3, `urllib3` 2.3.0, `requests` 2.32.3; `aiohttp` 3.11.14 has 33 and the build installed a **yanked** release.

- **The feed-server address guard** (disabled in dev by `FEED_SERVER_ALLOW_LOCAL=1`; covered by `tests/test_safe_fetch.py`).
- **Legal compliance**: GDPR (the public deletion log keeps text; I-05, I-06), the UK Online Safety Act, NCMEC duties, AdSense policy. Flagged as risks for a lawyer.
